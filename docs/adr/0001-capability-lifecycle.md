# ADR 0001：能力固化、版本管理与自动加载

- 日期：2026-10-19
- 决策状态：接受
- 实现状态：未实现

## 背景

个人助手需要把用户引导下成功完成的做法和纠正用于以后的任务。聊天记忆缺少稳定的适用范围、版本、验收和恢复契约；每次把所有历史重新输入模型也会增加成本和误用风险。

## 决策

在模块化单体中新增 capabilities 模块，采用“提炼候选 → 验证 → 授权范围内启用 → 匹配 → 固定快照 → 执行 → 反馈”的生命周期。版本化能力包由 Git 管理，启用状态由运行数据库记录；policies、workflows、approvals 各自维护规则、执行和审批事实。

优先实现显式 ID 加载与确定匹配，之后按需求增加语义检索。Skill 可以承载模型说明，但不得成为唯一持久化形式或授权来源。具体契约与验收见 [能力设计](../CAPABILITIES.md)。

## 未采用的方案

- 仅靠聊天记忆：不能可靠区分流程、一次性参数与操作授权，也难以测试和回滚。
- 让 Agent 自行编辑并立即执行 Skill：缺少候选验证和明确启用范围，容易把特例推广成默认规则。
- 全量能力注入上下文：上下文成本随能力增长，冲突与误匹配难以解释。
- 通用插件市场或微服务能力平台：当前无独立扩容/多团队发布需求，维护负担高于收益。

## 影响

增加能力版本、激活、评测、匹配记录和执行快照等概念，需要未来实现数据库迁移与接口。旧版本保留和规则兼容性成为维护责任。收益是复用、纠正、工具替换和任务恢复围绕同一组契约，不与某模型或 UI 绑定。本次只记录架构，不新增运行表或改变现有任务行为。
